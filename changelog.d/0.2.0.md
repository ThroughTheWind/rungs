# 0.2.0 — pending

Minor, not patch: twelve `feat:` commits landed since v0.1.3, and
[`cut-release`](../modules/release/skills/cut-release/SKILL.md) §1 says a feature decides the minor.

## Added

- `rungs doctor --explain` runs the detectors against a repository that never installed rungs, so
  the analysis can be read before anything is written (WI-038). Plain `doctor` now says the
  analysis exists rather than leaving it undiscoverable (WI-049).
- Detection recognises an external issue tracker as a *different paradigm* rather than an absent
  one, and `rungs add` stops on a detected paradigm instead of installing over it (WI-039, WI-043).
- `rungs backlog archive` moves a closed item to the archive and reconciles the board (WI-047).
- A self-test runner that executes each gate's fixtures, wired to run on every `rungs check` so a
  declared fixture that never ran is reported instead of counted as a pass (WI-045, WI-059).
- The `backlog-board-reconciled` gate, and the skill-extension opt-in that lets a repository extend
  a module's skill without the next `upgrade` overwriting it (WI-050, WI-058).

## Changed

- Detector applicability is a declared property of each gate with **no default** — a gate that does
  not say where it applies is an error, not an implicit "everywhere" (WI-052,
  [ADR-0007](../docs/decisions/ADR-0007-detector-applicability.md)).
- The docs site derives its structural counts (gates, hooks, modules, profiles) from the registry
  and refuses to build when they drift, replacing hand-typed numbers (WI-051).
- `modules/adr` 1.0.0 → 1.1.0, `modules/backlog` 1.0.0 → 1.1.0, `modules/session` 1.1.0 → 1.2.0.

## Fixed

- `rungs upgrade` re-registers a module's gates instead of silently leaving the registry at the old
  set, and updates the install record surgically rather than rewriting entries for files that have
  diverged (WI-054, WI-055; closes F-016, F-017).
- Four gate-set defects that the new self-test runner exposed, and the self-test mismatches it
  reported afterwards, which were localised to their real cause rather than suppressed (WI-056,
  WI-057; F-018).
- Link checking resolves a `file.ts:387` code reference instead of reporting it as a broken link
  (WI-042).
- The site's `REAL OUTPUT` label is only rendered above content that is genuinely captured command
  output; a summarised procedure is now presented as one (WI-046; closes F-011).
- The versions page states publication status by comparing against npm `latest` instead of testing
  equality with it, so v0.1.1 and v0.1.2 no longer read "npm publication pending" two releases
  after they shipped. `publishedVersion` was also two days stale, which had the current release
  advertising itself as unpublished while it was installable.
- The docs site type-checks clean again. Deriving the module inventory (WI-051) widened `rung` to
  `number` where the card component declares `0 | 1 | … | 5`, leaving `astro check` red for the
  rest of the cycle; the boundary now validates the rung against the ladder rather than asserting
  it, so a manifest with a bad rung is a build failure instead of a rendered badge.
- `rungs check <tier>` no longer answers `no gates registered — is this a rungs repo?` when the
  repo *is* a rungs repo and the tier simply matched nothing. It now names the tier, says how many
  gates it declined to run, and exits non-zero. The `cut-release` skill's gating step said
  `rungs check --tier full`, which selected zero gates on any repo whose gates are all `fast` — a
  release step that gated on nothing while reporting success (F-020).
